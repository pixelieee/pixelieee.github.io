**一句话结论：** DeepSeek Harness 用 Cordis 把会话日志、指令预算、Skill 和外接 MCP 记忆拆成独立插件；模型看到的只是从只追加日志派生出的 `surface`（当前视图），压缩只遮蔽视图不删原日志，连 Skill 清单是否重发都以 `surface` 上还能否看到它为准。<Src {...source} p="packages/compaction/compaction-basic/src/region.ts" l="492-510" /> <Src {...source} p="packages/skill/tool-skill/src/index.ts" l="344-355" />

读完这篇，你能搞清四件事：

1. 为什么换了仓库还能搜到上次发布的记录，而 DSH 自带的会话查询工具却查不到？
2. 会话压缩怎样在不删一行日志的前提下把旧对话换掉？为什么新消息在摘要生成期间进来，自动压缩和手动压缩的处理不同？
3. 为什么给项目指令设 600 字节预算，加上用户规则后总输出反而变成 879 字节？
4. 为什么磁盘上的 Skill 文件一字未动，压缩之后系统却会自动把相同的 Skill 清单再发一遍？

## 一张图看懂：一条经验的四种去向

DSH 用 Cordis 组装能力，不存在单一内置记忆库。要判断它「记住了没有」，先分清部署加载了哪些插件，再沿着下面四条通道查：

<FigDshArch />

| 载体 | 谁来持有 | 下一次怎么进入模型 |
|---|---|---|
| **会话事件与检查点** | Session 追加事件，JSONL（Zstd）/ SQLite 持久化 | 恢复或继续该会话时，按当前 `surface` 派生消息序列 |
| **用户与项目指令** | `agent-instructions` 读 `$DSH_HOME` 与项目链 | 首次请求注入基线；相关文件成功操作或切目录时更新 |
| **Skill** | `ctx.skills` 聚合各提供方，正文留在文件或提供方 | 先发布清单消息，模型调 `skill` 或用户敲 `/<name>` 时现读正文 |
| **外接长期记忆** | 默认关闭的 MCP 服务（如 Reference Memory） | 启用服务后由模型显式调工具读写，作用域归外部服务 |

有两个名字很像但完全不同的查询：`ctx.sessionQuery` 查的是 **DSH 自己的会话历史**；第三方 MCP 记忆查的是**独立维护的外部数据集**。<Src {...source} p="packages/session-query/session-query/README.md" l="28-49" /> <Src {...source} p="docs/user/guide/mcp-memory.md" l="5-21" />

## 会话日志与 surface：压缩只遮蔽视图，不删原日志

DSH 严格区分「原始事件日志」和「模型眼前的可见序列（`surface`）」：`readSession` 返回可回放的原始事件，`readSurface` 返回当前视图，读历史优先读内存中的活跃会话，否则冷读 JSONL（默认带校验 Zstandard 帧）或 SQLite。<Src {...source} p="docs/subsystems/persistence.md" l="341-346" /> <Src {...source} p="packages/session-query/session-query/README.md" l="9-13" />

压缩时，基本压缩后端先写 `compaction/summary` 事件，再追加一条带 `surfaceOp: replace` 的检查点消息，把旧区间从 `surface` 上遮蔽掉：

```ts title="packages/compaction/compaction-basic/src/region.ts · 507–510"
  session.append('user/message', checkpointMessage, {
    surfaceOp: { op: 'replace', startSeq: start, endSeq: end },
    sourceEventSeqs: [startEvent.seq, summaryEvent.seq, ...shadowedSeqs],
  })
```
<Src {...source} p="packages/compaction/compaction-basic/src/region.ts" l="492-510" />

注意 `startSeq` 和 `endSeq` 虽然是事件序号，切片时却按它们在**当前 `surface` 上的位置**截取闭区间——经历过多次替换后，新事件可能排在旧事件前面，直接按数字大小截取会抓错范围：

<FigDshSurface />

两个极见功力的工程边界：
- **摘要生成期间来了新消息怎么办？** 正常入口会先排队等压缩完成；如果 `surface` 在等待模型写摘要期间真的变了，**自动压缩**要求整条可见序列和测量时完全一致才提交，而**手动压缩**只要求选中的那一段仍然连续且未变——追加在选区外的新消息可以和旧选区的摘要并存。<Src {...source} p="packages/compaction/compaction-basic/src/index.ts" l="398-454" /> <Src {...source} p="packages/compaction/compaction-basic/src/region.ts" l="431-469" />
- **摘要没变短直接判失败；刷盘失败时内存视图可能已变。** 封装后的摘要若不小于原文，在替换发生前就报错退出；验证通过后先写内存事件再刷盘，若刷盘失败返回 `persistence` 错误，但内存中可能已可见新检查点。<Src {...source} p="packages/compaction/compaction-basic/src/region.ts" l="228-270" /> <Src {...source} p="packages/compaction/compaction-basic/src/region.ts" l="337-358" />

至于**新会话能不能查旧会话**：实验性 `tool-session-query` 的 5 个只读工具可搜索当前、已遮蔽和仅存于日志的事件，但跨会话查询严格要求调用方与目标会话的 **`cwd` 完全一致**——哪怕同属一个 Git 仓库的不同子目录也不能互查。<Src {...source} p="packages/experimental/tool-session-query/README.md" l="9-14" /> <Src {...source} p="packages/experimental/tool-session-query/src/workspace-access.ts" l="74-112" /> <Src {...source} p="packages/session-query/session-query-sqlite/README.md" l="59-69" />

## 工作区规则：两条独立的 64 KB 预算链

默认启用的 `agent-instructions` 在首次请求时读取两条规则链：用户链（`$DSH_HOME` 与共享 agents 根）和项目链（项目根一路到 `cwd`），兼容 `AGENTS.md`、`CLAUDE.md` 及 `.local.md`（同组去空白内容相同只留一份）。<Src {...source} p="packages/context/agent-instructions/README.md" l="27-44" /> <Src {...source} p="packages/context/agent-instructions/src/files.ts" l="430-450" />

关键在预算：**用户链和项目链各自拥有独立的 65,536 字节预算**，互不挤占；且同一链超限时，优先丢弃宽泛的根目录规则，再截断更具体的子目录规则。把真实渲染器设为每链 600 字节，实测 240 字节用户规则 + 800 字节根规则 + 240 字节子目录规则：

| 输入与每链预算 | 实际输出字节 | 被整份省略 | 被截断 |
|---|---:|---|---|
| 项目根 + 子目录，每链 600 | 600 | 根 `AGENTS.md` | `app/AGENTS.md` 留 186 字节正文 |
| 再加用户规则，每链 600 | **879** | 根 `AGENTS.md` | 子目录仍留 186 字节（未被挤占） |
| 三份文件，每链 2,000 | 1,659 | 无 | 无 |
<Src {...source} p="packages/context/agent-instructions/src/render.ts" l="363-480" />

会话运行中，外部编辑器改了文件不会自动推送消息；但模型自己通过工具成功改动或打开了相关目录文件，插件会在下一步补上新规则、替换或移除通知。<Src {...source} p="packages/context/agent-instructions/README.md" l="9-13" /> <Src {...source} p="packages/context/agent-instructions/src/index.ts" l="330-369" />

## Skill：层级优先于排名，清单重发看 `surface`

DSH 的 Skill 体系比多数框架更严谨，拆成三层判断：

1. **同名裁决：作用域层 > 同层数值排名。** 靠近当前 Agent 的作用域层直接压过外层；只有**同一层内**才比数值 rank（默认项目 `.dsh/skills` 100 > 项目 `.agents/skills` 200 > 自定义 300 > 用户 DSH 400 > 用户 agents 500 > 随包 600）。<Src {...source} p="packages/skill/skill/src/index.ts" l="553-586" /> <Src {...source} p="packages/skill/skill-filesystem/README.md" l="44-58" />
2. **两条独立调用开关。** 每步开始前，`tool-skill` 把允许模型调用的条目（名称 + 简介）发布为带来源标记的清单消息，调 `skill` 工具时现读磁盘正文；用户手敲 `/<name>` 则走独立的 `userInvocable` 检查。因此可以只允许人工 `/<name>` 而禁止模型自动调用。<Src {...source} p="packages/skill/tool-skill/src/index.ts" l="133-255" /> <Src {...source} p="packages/skill/skill-filesystem/src/index.ts" l="212-234" />
3. **文件未动却重发清单的真相。** `tool-skill` 决定要不要发新清单，比较的是两样东西：**本次发现的摘要**（仅含名称、简介和发现是否完整——不含正文）与**上一条仍在 `surface.nodes` 里的清单消息**。所以只改 Skill 正文时清单保持安静；一旦压缩把旧清单遮蔽出 `surface`，即使文件一字未动，下一步也会自动把相同清单再发一遍：<Src {...source} p="packages/skill/tool-skill/src/index.ts" l="290-356" /> <Src {...source} p="packages/skill/tool-skill/src/index.ts" l="380-399" /> <Src {...source} p="packages/skill/tool-skill/tests/tool-skill.spec.ts" l="585-614" /> <Src {...source} p="packages/skill/tool-skill/tests/tool-skill.spec.ts" l="689-744" />

## 外接记忆：跨项目靠共享图谱，写入和查询有两处坑

官方给出 Memorix、MCP Reference Memory、Engram 三套默认关闭的记忆配置——DSH 只管拉起或连接 MCP 服务、暴露工具，底层存储、去重和作用域完全归外部服务所有。<Src {...source} p="docs/user/guide/mcp-memory.md" l="5-33" /> <Src {...source} p="apps/cli/config/examples/mcp-memory/mcp-reference-memory.cordis.yml" l="1-13" />

直接对官方示例锁定的 `@modelcontextprotocol/server-memory@2026.7.4` 跑跨项目实验（项目 A 写入实体 `release` 观察值 `refresh atlas` + 指向 `manifest` 的 `requires` 边 → 退出进程 → 切到项目 B 打开同一图谱文件），立刻露出三处必须留意的边界：

| 在项目 B 新进程里的查询 | 命中实体 | 暴露的真实行为 |
|---|---|---|
| 同图谱，搜 `ATLAS` | `release` | 只要指向同一 `MEMORY_FILE_PATH` 就能跨仓库命中，但**不带邻居 `manifest` 的观察值** |
| 同图谱，搜 `map` | 空 | 本服务只做大小写不敏感的**字面子串匹配**，不做语义检索 |
| 同图谱，`open_nodes("manifest")` | `manifest` | 必须走第二跳工具调用，才能读到邻居的 `owner: ci` |
| 同目录，换空图谱读全图 | 空 | 跨项目共享取决于打开哪份图谱文件，而非当前目录 |

还有一个极易踩中的写入静默去重：对已存在的 `release` 再次调 `create_entities` 附带新观察值 `SECOND_NOTE`，服务**成功返回空新增列表**，随后搜索为空——给已有实体补事实必须调 `add_observations`。[固定版本服务源码](https://unpkg.com/@modelcontextprotocol/server-memory@2026.7.4/dist/index.js)

## 踩坑清单与进化边界

<Infer /> 基于源码与实测的四个核心判断：

1. **没有内建的回合后自动复盘器**：DSH 的热更新只证明「磁盘改了，下次能读到」；谁来把经验写回文件或图谱，默认仍靠人、私有插件或显式调用外接 MCP 工具。
2. **「跨项目记忆」演示先看工具名**：用同一图谱文件的 MCP 服务天然跨仓库，而内置 `tool-session-query` 连同仓库子目录都严格按精确 `cwd` 隔离。
3. **知识图谱查到边 ≠ 读到邻居属性**：Reference Memory 的 `search_nodes` 只给邻居名字和关系，回答「谁维护它」需要模型主动多走一跳 `open_nodes`。
4. **规则缺席先看省略记录，再看路径**：单链 64 KB 预算满了会静默省略根 `AGENTS.md` 或截断子目录文件，文件存在不代表全文进去了。

## 回看开篇的四个问题

1. **为什么换了仓库还能搜到上次发布的记录，而 DSH 自带的会话查询工具却查不到？** 跨仓库命中来自共享同一 JSONL 图谱文件的外接 MCP 记忆服务；内置的 `tool-session-query` 只允许子代理在**精确匹配的同一个 `cwd`** 下检索会话，换仓库甚至进子目录都会被隔离。
2. **会话压缩怎样在不删一行日志的前提下换掉旧对话？新消息在摘要期间进来时，自动压缩和手动压缩有何不同？** 压缩只往日志末尾追加一条带 `surfaceOp: replace` 的事件，把旧区间从当前 `surface` 视图里遮蔽掉、底层原日志一行不删；摘要生成期间若插入新消息，自动压缩直接丢弃本次摘要下轮重算，手动压缩则保留摘要并把新消息排在摘要后面。
3. **为什么给项目指令设 600 字节预算，加上用户规则后总输出反而变成 879 字节？** 指令预算（默认 64 KB）是按「项目链」和「用户链」两条链**分别独立计费**再拼合的，单链设 600 字节时两条链合计上限其实是 1,200 字节。
4. **为什么磁盘上的 Skill 文件一字未动，压缩之后系统却会自动把相同的 Skill 清单再发一遍？** 工具重发清单不只比对修订号，还会检查上次发出的清单是否仍在当前 `surface` 视图里可见；一旦压缩把旧清单遮蔽掉，下一轮就会自动补发一份。
