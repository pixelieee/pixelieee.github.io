**In one line:** Frontier harnesses already look alike on “can I resume?”. They split on **where truth lives, who touches the outside world, how agents talk, and how you embed the thing**. DeepSeek Harness derives model-visible history from an append-only log, yet the loop still calls the model and tools—that gap between “log is truth” and “loop only emits commands” is still open.

This note is not a product review and not the memory/skills series. It exists so you can judge Pure Agent’s end-state without being captured by one vendor story.

After reading you should answer:

1. Is “append-only JSONL” the same as “the log is the sole source of truth”?
2. Why can dsh say “everything is a plugin” and still not be a pure core?
3. How do products build “one agent talks to the user; others work in the background”?
4. What problem do in-process libraries, on-demand subprocesses, and always-on app servers each solve?
5. Where is the seat nobody holds firmly for a TypeScript kernel?

## Axis 1: Where truth lives

<FigTruthPaths lang="en" />

**Claim A: resumable dump.** Claude Code writes JSONL and reads it back. Codex has rollout JSONL. pi stores a JSONL tree with `id` / `parentId`. That means chat can come back—not that the loop trusts the file *now*.

**Claim B: model history only folds from the log.** Among the seven, DeepSeek Harness says this in public source: the LLM message history is *derived* from the log, never stored separately; replay is re-derivation. The loop builds requests via `session.deriveMessages()`.

| | On disk | What the loop trusts now | Sole log truth? |
|---|---|---|---|
| Claude Code | JSONL transcript | Docs silent; subprocess owns the file | Not claimed |
| Codex | Memory + rollout + state DB | `run_turn` reads memory history | No; rollout write failure does not stop the turn |
| pi | JSONL tree | In-flight memory; finished context via SessionManager | For settled tree yes; in-flight no |
| OpenCode | SQLite session / message / durable event | Runner reads recorded Session history | Commit record, not command-level fold |
| Hermes | SQLite | Still feeds a message list to the model | Canonical copy, not the fold engine |
| Alma | Product memory objects | Docs do not describe an event log | N/A |
| dsh | Append SessionEvent | `deriveMessages()` | **Yes for model-visible history** |

Append-only is common. **Treating the log as the loop’s only input** is not. OpenCode / Hermes / Codex persist hard; “what next” still lives in imperative loops and memory.

<Infer /> Learning “write JSONL” buys the entry ticket, not the difference. The difference continues on axis 2.

## Axis 2: Who runs side effects

<FigExecSplit lang="en" />

dsh stacks two claims: history comes from the log; the loop still `llm.stream`s and `tools.execute`s. In memory, tools `append('tool/call')` then `dispatch`. Disk write-ahead is a **removable** plugin (`dsh-session-checkpoint-policy`). Architecture docs say every part of the product is a plugin—including the agent loop. Crash recovery reconstitutes an interrupted turn via `interruptedTurnClosers`. Strong—and the actor is still a patchable `AgentLoop`.

| | Loop executes? | How hard is write-ahead? |
|---|---|---|
| Codex | Yes, `run_turn` | Rollout not fail-closed |
| pi | Yes, `tool.execute` | Append then run; no forced fsync |
| OpenCode | Yes | Start tools after related events; SQLite claim to continue |
| Hermes | Yes | Flush session DB before tools; fail → skip |
| dsh | **Yes** | Hard in memory; disk is a plugin |

**“Event-driven” ≠ “the loop does not execute.”** Pizza replaces a chat `while` with EventStore subscriptions; the LLM handler still `await`s the model. OpenSuperAgent polls every 400ms and hands a full turn to Pizza. They answer “who woke whom,” not “can side effects enter the core.”

The empty-seat sentence:

> The log is sole truth; `reduce` only emits effects; model and tool calls live in the interpreter; replay verifies those effects instead of redoing I/O.

dsh finished the first half (model history). The second half is still open. The old runtime string `log-reconstruction desync` is gone from `2e39e70` with the removed invariant plugin.

## Axis 3: How agents talk

<FigMsgPatterns lang="en" />

1. **Subagent as a tool** — nested turn, result as tool result (Claude Code subagents, many “background: true” switches).
2. **Peer session + mailbox** — Codex mailbox preempt; pi steer / followUp; dsh `agent-message` then `steer` into one inbox (types stay distinct). Task boards in dsh do **not** wake agents.
3. **Ledger outside the loop** — OpenSuperAgent SQLite inbox + pump; dsh-superagent-prototype `relay` / `notice`. Progress is a projection.
4. **Product teams** — Claude Agent teams (experimental); Hermes `delegate_task`; Alma talks workflows and human approval, not subagents.

| | User barge-in / peer / external |
|---|---|
| Most products | **Not** unified |
| dsh | Same session log; kinds stay separate |
| Pizza | Cross-agent `_tell` often wrapped as prefixed `USER_MESSAGE` — one door, lost types |

<Infer /> One inbox helps; disguising peer talk as the user’s words accrues debt. Cleaner shape: one `Input` pipe with `user` / `peer` / `external` fields.

## Axis 4: How you embed

<FigEmbedModes lang="en" />

| | Main embed | Always-on? |
|---|---|---|
| Claude Code | One subprocess per `query()`, stdio | Managed Agents hosted; not a local app-server |
| Codex | Public TS SDK = `codex exec` + JSONL | app-server exists; TS SDK does not default to it |
| pi | In-process `createAgentSession()` | `pi --mode rpc` is a long-lived child; no port by default |
| OpenCode | In-memory SDK routes | Optional HTTP, localhost + password |
| Hermes | In-process Python | Gateway is for IM, not an embed JSON-RPC core |
| Alma | No local SDK | Hosted HTTP / MCP |
| dsh | In-process Cordis; public SDK spawns `dsh` | Web profile listens on `127.0.0.1:3080`; sdk / acp / headless do not |

For embedders, the default is almost always a **library** or **spawn when needed**. Always-on servers follow multi-client / IM / remote-desktop reasons. That is also why “everything is a plugin” cannot copy from dsh unchanged: if `reduce` itself is swappable, you erase the still-empty claim that the actor never enters the core.

## The empty seat

<FigEmptySeat lang="en" />

Nobody yet holds all four: TypeScript in-process import; model history (and effects) derived from an append-only log; `reduce` never does I/O; those guarantees are not removable plugins.

Pizza / Restate / Temporal prove event subscription, journal replay, and activation boundaries at production scale—while handlers still do I/O, or they are not a terminal coding-agent kernel. The seat stays empty.

## Checklist (fill after reading)

**A. Truth** — resumable dump / derive model history (dsh) / effects must enter the log first (empty seat)

**B. Execution** — loop may call model & tools / loop only emits effects / disk write-ahead as plugin (dsh) / as core guarantee

**C. Messaging** — subagent-as-tool / peer + mailbox / ledger outside loop / unified Input with peer types

**D. Embedding** — in-process only / library + spawn bridge / default always-on app-server

**E. Extension** — everything is a plugin including the loop (dsh) / small immovable core, removable outer modules

**F. Vocabulary** — Primitive / Module / Capability (instead of casual “blocks”)
